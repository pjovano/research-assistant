## Builds

| Step | Content |
| --- | --- |
| A5.1 | `core/templates/domain/`: an empty `AGENTS.md` contract in the five-section shape with `CLAUDE.md` importing it, `vendor/agent-core/SOUL.md`, and `USER.md` (A6), a `.gitignore` naming `/USER.md` and the test that fails if git tracks a `USER.md`, the `decision-gate` CI job, a glossary, an `audit/checks.py` stub, a test runner, CI calling the core audit, the `vendor/agent-core/` subtree and its symlinks, a default `.obsidian/` config (today's `obsidian/graph.json` pattern, made general) |
| A5.2 | `new-domain`: copies the template; asks the mandate, `handles`, `exposure`, `policy`, and `unattended`; writes `domain.json`, its `vault` included unless the vault is declined; prints the settings block from `domain.py settings` |
| A5.3 | The folder step: each new domain is an Obsidian vault by default (`PLAN.md` §1). The domain gets a folder of its own in `~/Documents`, with `write` access, made a vault by copying the template's default `.obsidian/` config, and `domain.json`'s `vault` names it; the user MAY decline the vault. Then which other folders in `~/Documents` the domain works on, existing or new, and with what access. Folders are created on the Mac at the switch, NEVER in the cloud |
| A5.4 | A domain with sensitive data runs with `unattended: none`, no network hosts in `policy`, and its folders `sensitive: true` by default |
| A5.5 | `domain.py` reads `vault`: absent, or the name of one folder `folders` lists with `write` access; it refuses any other value and names the manifest; `manifests` lists each domain's vault |
