## Builds

`audit.py lint` gains row types, each row `{rule, file, line, detail,
fingerprint}`: `prose`, `xref`, `redundancy`, `staleness`, `special`, `code`,
with the rules of the source plan's U3 table.

| Piece | Content |
| --- | --- |
| `xref` | written against `model:` and the stage table's Model column only; G17 extends it to tiers. The domain's `audit/checks.py` names where its contract keeps the stage table, the hook list, and the operation tables |
| `special`, sign 6 | a commit with neither `Defect-class:` nor `Change-class: refactor\|feature — <what>` (X2) |
| Ruff | the extra rules (`PLR0913, PLR0915, PLR2004, C901, FBT, BLE, S110, ERA, ARG`) run inside `audit.py lint`, ratcheted by fingerprint; `pyproject.toml` keeps `E4, E7, E9, F` |
| Ratchet | the baseline gains `acknowledged: {fingerprint: reason}`; a fingerprint is the rule, the file, and a hash of the normalized line; `lint --new` prints only unacknowledged rows; the first run acknowledges today's rows on the user's word |
| New subcommands | `acknowledge` and `dismiss`, each with an `excludedCommands` entry in `.claude/settings.json`, in this PR: spike item 2 found the session may edit the settings, so no settings patch |
| Hooks and CI | the post-edit Markdown hook adds `prose --new` for the edited file; CI fails on new `xref` and `special` rows; `prose` and `redundancy` report without failing |
| No new dependency | voice and noun clusters use regex heuristics |
| `weight` | the words of each instruction file and of the whole instruction text; the always-loaded text (the contract, and every skill's and worker's `description`) counted on its own; the counts kept in the audit baseline. Words are counted as `clean-prose`'s STE rules count them (U2) |
| Word ratchet in CI | CI fails a PR that grows the instruction text, the always-loaded text or the rest, unless the growth sits in a `Change-class: feature` or a `Defect-class:` commit and the PR body states the words added and the rule each serves. A refactor, an audit fix, U2b's splits, G21's capability names, and Check 9's practices never grow the text. Each audit report names the always-loaded text's growth since the last run first. A merged PR that cuts the text lowers the baseline's counts (`PLAN.md` §1, "New: the instruction text only shrinks") |
| `redundancy` gate | `redundancy` rows fail CI once the bench measures their precision at 0.9 or higher; until then they report |

**The first acknowledgement needs the user's word.** The implementer MUST NOT
acknowledge today's rows in bulk on its own: the PR carries the rows and the
`needs-decision` label, and the bulk acknowledgement lands after the user
answers.
