## Builds

The source plan's PR 15 table for macOS and the `mac-local` profile alone,
so that anyone with a capable Mac, Obsidian, and Zotero can install the setup,
with these rules from `PLAN.md` §3:

| Rule | Content |
| --- | --- |
| Primary checks | the health job installed and loaded; no iCloud placeholder in the library or the inbox, which stands in for Optimize Mac Storage off. `doctor` NEVER checks the Remote Control job: the job lives at `agent-core`'s root, and `bin/remote_control.py status` checks it (P5+M3) |
| `--no-jobs` | skips the jobs; the switch runs it at §6 step 4.4, and every test install in CI runs it. No detection of a host without a scheduler: the product runs on an always-on machine |
| Hooks | `bootstrap` sets `core.hooksPath` to `.githooks` (X1, G18) |
| macOS only | `bootstrap` builds the venv from `requirements.lock` with the contract's `uv pip sync` command, writes `machine.json` from `mac-local` if absent, creates the inbox and the state directories, and pulls the local models `mac-local` names. `doctor` checks what the source plan's table names for `mac-local`. Other OSes, the profiles `linux-local` and `api-light`, the split locks (P14), and the API adapters' lines are deferred (`PLAN.md` §3, "Deferred"): NEVER build them in this item |
| Terminal only | `bootstrap` runs from a terminal, never inside the agent's sandbox |
| Remote Control | installed with `bin/remote_control.py install --apply` in `agent-core`: by the switch (§6 step 4.6), or by a new install's README step; never by `bootstrap` |
