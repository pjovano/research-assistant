## Builds

`audit.js` ships from the core, on the `ingest.js` pattern: script steps
through `relay`, workers through `agent()` with a schema, answers files in the
scratch directory under `audit/<run>/`. Arguments: `{scope, budget,
partition_tokens, loop, fix, practices_max_age}`. Phases, workers, and the
finding schema are the source plan's U5 tables; the promotion log is
`audit.py promotions`.

Each new worker's instructions carry its check text in full and the two
false-positive guards: a worker inherits nothing. Each names its model as G17
sets it; a worker that lands after G17 carries `tier:` from the start.

The core's audit skill is rewritten around the workflow: run it, read the
report, accept on the user's word. `vault-audit` stays a thin research skill.

## Spike findings that bind

| Finding (`spikes.md` item 4) | Consequence for U5 |
| --- | --- |
| The Workflow tool runs min(16, CPUs − 2) agents at once: 2 on the 4-vCPU VM | size `partition_tokens` and `budget` so a capped run finishes in the cloud; state the run's wall time on the bench |
| Each agent costs about 68,000 tokens before it does any work | a run of 20–40 dispatches costs 1.4–2.7 million tokens in overhead alone; the default `budget` caps a run under the 10-agent guideline, and rotation covers the rest across runs |
