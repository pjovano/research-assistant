## Why first

The rerun measured the full suite at 4,965 tests in 118 s on the 4-vCPU cloud
VM, and the post-edit hook at 2 min 10.5 s after every Python edit. Every later
item pays that wait per edit until X1 lands.

## Builds

| Piece | Content |
| --- | --- |
| Affected modules | After an edit to a `.py` file, `checks-after-edit` runs the test modules whose import closure holds the edited module, read from the source by `ast`, never by importing it. An edit to a test module runs that module. An edit to a test helper runs every test module that imports the helper. |
| Fallback | If the import graph cannot be built (a file fails to parse), the hook runs the full suite. |
| Edits outside Python | An edit to a `.md` file keeps today's checks: the audit linter's `works` check. |
| Full suite, pre-push | `.githooks/pre-push` runs the full suite, ruff, and the audit linter. `bin/cloud-setup.sh` sets `core.hooksPath` to `.githooks`. On the primary, `bootstrap` sets it (P15); until then the rehearsal sets it. |
| Full suite, CI | unchanged: CI runs the full suite on every PR. |
| Worktree edits | The hook resolves its project root from its own file under `$CLAUDE_PROJECT_DIR`, so an edit inside a git worktree is either outside the checked root or checked against the main checkout. The hook MUST check the work tree that holds the edited file, found with `git rev-parse --show-toplevel` from the file's directory, when that tree is a worktree of this repository. |
| Timeouts | `SUITE_TIMEOUT_SECONDS` and the hook's `timeout` in `.claude/settings.json` sized for the affected-module run; the full-suite fallback keeps today's budget. |
| Contract §5 | "Run the test suite from the repository before and after every code change" becomes: the hook runs the affected test modules after every edit; the full suite runs before every push and in CI. The hook paragraph of §5 states the same. |

## Tests

- A fixture package with three modules and four test modules: an edit to each
  module selects exactly the test modules whose import closure holds it.
- An unparsable file makes the hook run the full suite.
- An edit inside a worktree is checked in that worktree (a temporary repository
  with one worktree).
- The pre-push hook fails when one test fails.
