## Builds

Two PRs: the core's first, then the domain's. The domain PR names the core PR
and merges after it.

### The core's PR, in `agent-core`

| Piece | Content |
| --- | --- |
| Package | `core/lib/agent_core/`, the one package of the core's code, so that no core module shadows a domain module of the same name (`_ports`, `_adapters`) |
| Ports | `agent_core/_ports/host.py`: `Scheduler` (`install`, `installed`, `remove`), `Notifier`, `SystemReadings`, with `Job`, `Notice`, and `Level`, moved from `research-assistant`'s `lib/_ports/host.py`, where P1 declared them |
| launchd adapter | `agent_core/_adapters/host/`: builds a plist from a job's label and contents, hard-coded today at `lib/_health/installer.py:40` and `lib/_health/launch_agent.py:32-42` of `research-assistant`; implements `remove` with `launchctl bootout` |
| macOS readings and notifiers | `SystemProbes` (`_health/sampler.py`), `DesktopNotifier`, and `RemindersNotifier` (`_health/notifier.py`), moved from `research-assistant` as the macOS adapters |
| `Level` | one enum, `normal / elevated / serious / critical`; each adapter's mapping table and its tests |
| Remote Control job | `bin/remote_control.py` at `agent-core`'s root, outside `core/`, so that no domain carries it. The job: `caffeinate -i claude remote-control --spawn same-dir`, `KeepAlive`, working directory an argument, `~/Developer/research-assistant` until the dispatcher is built, a label other than `local.claude-remote-control`, no `--name`; it keeps the hand-written plist's other keys (`RunAtLoad`, `ThrottleInterval` 30, `--no-create-session-in-dir`, a `PATH` reaching `claude` and Homebrew, a log under `~/Library/Logs/`) and resolves `claude` at install time. Commands: `install [--apply]`, `uninstall [--apply]`, read-only form first, and `status` |
| Tests | `tests/ports/` at `agent-core`'s root: the contract suites of the three ports, moved from `research-assistant`'s `tests/ports/`; the plist builds; the Remote Control job's tests |
| `core/README.md` | the `lib/` row names the host ports (P5+M3) |

### The domain's PR, in `research-assistant`

| Piece | Content |
| --- | --- |
| Subtree pull | `git subtree pull --prefix vendor/agent-core` brings the core's PR in (`PLAN.md` §3, "A core pull") |
| Module path | `vendor/agent-core/lib` joins the module path in one module of `lib/` that every importer of the core reaches first, and in the test support's `ModuleSearchPath` beside `lib/` |
| Ports | `lib/_ports/host.py` loses the three ports, `Job`, `Notice`, and `Level`; every importer imports them from `agent_core`. NEVER re-export a moved name from `lib/_ports/host.py`: a re-export is a copy that drifts |
| Providers | `lib/providers.py` resolves `scheduler`, `notifier`, and `system_readings` to the core's adapter classes |
| Health | `_health/` keeps the detectors, the workloads, the journals, the report, and the health job's definition; the code moved to the core is deleted from it; `machine-health/health.py` builds its adapters through `providers`; `health.py uninstall [--apply]`, read-only form first; the health job takes a new label |
| Hook | `HealthWatcherHook` in `lib/harness_hooks.py` installs through the core's `Scheduler` |
| Skill | `machine-health`: `uninstall` |

Code only: the jobs are installed at the switch (§6 step 4.6), never before.
The hand-written plists are NEVER read, edited, or removed by this code: the
rollback reloads them.

`SyncedFolder` stays in `research-assistant` (P6+M4). The systemd adapter, the
Linux readings, `notify-send`, ntfy, `Accelerator`, `Trash`, and `Locations`
are deferred (`PLAN.md` §3, "Deferred"): NEVER build them in this item.
