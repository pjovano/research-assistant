## Builds

| Piece | Content |
| --- | --- |
| Ports | `Scheduler` (`install`, `installed`, `remove`; a job is a label and its contents), `SystemReadings`, `Notifier`; adapters for macOS (moved) and Linux (new) |
| launchd adapter | builds a plist from a job's label and contents, hard-coded today at `lib/_health/installer.py:40` and `lib/_health/launch_agent.py:32-42`; implements `remove` with `launchctl bootout` |
| systemd adapter | a user `.service` and `.timer`; `systemctl --user enable --now`, `disable --now` |
| `Level` | one enum, `normal / elevated / serious / critical`; each adapter's mapping table and its tests |
| Health | `machine-health/health.py` builds its adapters through `providers`; `health.py uninstall [--apply]`, read-only form first; the health job takes a new label |
| Hook | `HealthWatcherHook` in `lib/harness_hooks.py` installs through `Scheduler` |
| Remote Control job | `caffeinate -i claude remote-control --spawn same-dir`, `KeepAlive`, working directory `~/Developer/agent-core`, a label other than `local.claude-remote-control`, no `--name`; keeps the hand-written plist's other keys (`RunAtLoad`, `ThrottleInterval` 30, `--no-create-session-in-dir`, a `PATH` reaching `claude` and Homebrew, a log under `~/Library/Logs/`); resolves `claude` at install time; `install [--apply]` and `uninstall [--apply]`, read-only form first |
| Skill | `machine-health`: the Linux readings and what their levels mean; `uninstall` |

Code only: the jobs are installed at the switch (§6 step 4.6), never before.
The hand-written plists are NEVER read, edited, or removed by this code: the
rollback reloads them.
